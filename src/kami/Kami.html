@Doc：為 AI 而生的語義文件格式

每一代文件格式，都在解決那個時代最核心的問題。Word 解決了編輯，HTML 解決了顯示，Markdown 解決了人類易寫性，JSON 解決了資料交換，JSX 解決了元件組合。但沒有一種格式，是真正為 AI 生成內容而設計的。

Semantic First, Layout Later. 語意優先，排版在後。

為什麼需要新的格式

LLM 讀 Markdown 沒問題，問題出在反過來：讓 LLM 生成 Markdown 並交給下游程式解析時，輸出結構幾乎無法被可靠保證。縮排歧義、巢狀清單漂移、表格損壞、parser 方言差異，每一項都是實務中的地雷。

IMPORTANT核心觀察 Markdown 沒有語義意圖。它無法表達「這個按鈕是 primary variant」，也無法表達「這張表格需要斑馬紋」。

HTML 可以表達任何東西，但代價是把展示邏輯寫死在結構裡。這曾經被認為是優點。同一份內容要渲染到不同平台？重寫。要讓 AI 生成穩定的 HTML？面對幻覺標籤與未閉合元素的風險。

MDX 的取捨

MDX 將文件與程式碼融合，為人類開發者提供極高的表達能力。但這種自由度對生成式模型而言意味著另一件事：更高的語法不穩定性。

dimensionmdxdoc
本質定位把文件變成程式把文件變成語義資料
AI生成穩定性容易語法崩潰確定性語法
括號語義多重混淆全域唯一即Content
Token成本冗長樣板代碼語法極度壓縮

@Doc 的設計哲學

Semantic First
區塊節點描述的是文件的語意（What），而不是呈現方式（How）。因此 @Doc 不提供 
@div
、
@span
、
@flex
這類版面節點。
  • 降低學習成本
  • 避免與 Email、Mention 系統衝突
  • 提高 AI 解析穩定性
  • 提高編輯器容錯能力
  • 保持 DSL 的可擴充性
  • 建立穩定且可預測的 AST
TIP設計取捨 `@cols` 與 `@data` 順序固定且皆為必填，這是刻意的設計取捨——犧牲一點靈活性，換取 Parser 與 AI 生成內容時的高度可預測性。

Known Command Recognition

@Doc 採用「只有已知指令具有語法意義」的原則。當 Lexer 掃描到 

@
時，會依照優先順序判斷：若後續為 
@@
，解析為單一純文字 
@
；若符合已註冊指令名稱，進入對應語法解析流程；否則整段視為普通文字輸出。

範例對照表 輸入 
@mark[hello]
會被解析為 mark 節點。 輸入 
@@mark
會輸出純文字 
@mark
。 輸入 
test@example.com
保持為純文字，不會誤觸發解析。
WARNING常見誤解 不要以為所有 
@
開頭的字串都會被解析——
@GitHub
、
@unknown
這類未註冊指令，Lexer 會直接退回純文字模式。

節點總覽

結構型區塊

標題、段落、引用、清單、程式碼、圖片、表格、分隔線，這八種構成了文件的骨架。 


interface DocASTNode {
  type: string;
  content: (DocASTNode | string)[];
}

容器區塊

@details
與 
@card
提供了可摺疊與可強調的容器語意，不涉及任何樣式假設。

標註區塊

NOTE 這是一般性補充資訊，讀者可依需求選擇性閱讀。
CAUTION 在 Strict Mode 下，未閉合的區塊會直接拋出 
DocSyntaxError
，不會嘗試靜默修復。

小工具區塊

@tabs
與 
@mermaid
屬於 Widget Blocks，前者用於多分頁內容切換： 

@Doc
的語法層完全由 EBNF 定義，Lexer 與 Parser 對照同一份 Command Registry 運作。

Renderer 可以自由決定輸出目標，包含 HTML、React、PDF、DOCX、Discord、Terminal，甚至是 AI UI。

Kami Adapter 是 Renderer 生態中的一個成員，示範了同一份 AST 如何映射到不同的視覺規範。

行內語意節點

文字格式化節點包含 粗體、斜體、底線、刪除線，以及可自訂樣式的 標記文字。

語意行內節點則涵蓋數學與科學符號：E = mc2，H2O。也包含鍵盤按鍵標示，例如按下 Ctrl + C 進行複製，或 Cmd + Shift + P 開啟命令面板。

連結節點會依內容自動推導 URI Scheme：詳見官方 GitHub Repo，或寄信至聯絡信箱，也可以直接撥打客服專線。

    結語

    @Doc 的核心目標並非取代 Markdown，而是建立 Human Editable、Machine Deterministic、AI Friendly、Cross Platform 的新一代文件中介格式。

    Core Principle
    HTML 是 Renderer。Markdown 是 Renderer。React 是 Renderer。 而 @Doc 是 Source of Truth。
